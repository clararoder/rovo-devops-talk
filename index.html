Jira UI. Automation. Agent assignee. Terminal. Same Rovo Dev underneath — pick the surface that fits the moment.
Way 1 · Jira UI

One click.
One draft PR.

Rovo Dev lives in the Jira sidebar. Open a ticket, hit Generate Code, pick a repo. Done.

Best for: PMs and tech leads working ticket-by-ticket.

RRA-1
Add GET /deployments/:env endpoint
StoryFix Version: 1.1.0
  • User story + acceptance criteria
  • Response format specified
  • Repo: release-rocket-api
RRA-1 has a clean user story. The more concrete the ticket, the better the result.
Way 2 · Automation

One label is all
it takes.

Tech lead sets a label. Rovo kicks off. By morning, the draft PRs are ready.

Best for: zero-touch backlog grooming across a whole team.

This scales across the whole team. Draft PR, not auto-merge. Review stays with humans.
Way 3 · Agent assignee

Hand it off
like to a teammate.

Set the ticket's assignee to the Rovo agent. It picks it up — same flow your team already uses for any other handoff.

Best for: teams that already route work through the assignee field.

No new ritual. If your team already routes work via assignee, Rovo just becomes another teammate. Works hand-in-hand with automation: rule sets assignee = Rovo, agent takes over.

Custom actions · already shipping

Skills,
from any Forge app.

Any Forge app — yours or from the Marketplace — can already register custom actions. Agents call them like built-in skills. The platform is open today; the Marketplace catalog is just starting to catch up.

Example: "Diagram the new auth flow." Draw.io Whiteboards & Diagrams registers a Forge action — Rovo calls it, and the draw.io file lands in Confluence.

Marketplace draw.io · Generate diagram custom action
auth-flow-v2.drawio
Important framing: this is already possible — Forge apps can register custom actions today, agents can call them. It's just not broadly used yet. Anyone can build a Forge app and ship a custom action; the Marketplace catalog hasn't caught up. As more apps (draw.io, Smart Links, your in-house DevOps tool) register actions, the agent's reach grows without Atlassian shipping every skill themselves. The draw.io example sits at the Release station because diagrams ship with the release.

No ticket form. No license portal. No help-desk queue. An employee just asks — in the same channel where the rest of work happens.

Routine IT work — licenses, accounts, board access — eats 5–15 minutes per request. Times hundreds a week. The agent finishes in under three.

Walk left to right. (1) User pings @helpme in Google Chat. (2) The chatbot does RAG over Confluence — answers when it can, otherwise files a Jira ticket. (3) Jira automation fires a webhook event that wakes Claude / Rovo Dev on a virtual machine. (4) Inbox Agent decides — auto-resolve, escalate, or route. (5) Triage Agent picks the right specialist. (6) Specialists are pluggable: SaaS-specific (Miro, GitHub, Calendly, Billomat, Figma...), plus a Coding Agents row and a Generic fallback for unmatched requests. Each specialist drives its target tool via API where one exists, otherwise via Chrome DevTools MCP + a headless browser. Dashed line: clarifying questions loop back to the user.
Takeaway · Part 2

The pattern:
Inbox → Triage → Specialized.

Inbox Agent

Reads, categorizes, decides: auto-resolve, ask back, or escalate.

Triage Agent

Picks the right tool, the right action, the right user. Dispatches.

Specialized Agents

Drive the SaaS — API where available, headless browser where not.

Browser-native control is the unlock: any tool with an admin UI is automatable, no vendor integration required.

Three roles, mirrors how a real IT team works: inbox decides, triage routes, specialists act. Browser-control means you can apply this to any tool — license management, board cleanup, calendar admin — without waiting on vendor APIs. That's the bridge from "Rovo answers questions" to "agents take action."
Live Demo · @helpme, end-to-end

From chat message
to GitHub seat —
no hands.

Single demo, end-to-end. (1) In Google Chat: @helpme I need a GitHub license. (2) Chatbot replies asking for confirmation (free seat vs. Copilot). (3) On confirm, ticket lands in Jira; webhook fires. (4) Agent on the VM wakes up: Inbox classifies, Triage routes to the GitHub specialist. (5) GitHub specialist drives the admin UI via Chrome DevTools, grants the seat. (6) Reply lands back in chat: "done — you've been added to seibert-group/engineering." Fallback: screen recording if anything stalls. Total wall-clock: ~30 seconds.
